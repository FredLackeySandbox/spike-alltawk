## Non-actionable ambiguities and risks

### Karma, warning points, and reputation scoring

- **Affected schema item:** `docs/schemas/identity.yaml`, object `Identity`; `docs/schemas/moderation-action.yaml`, object `Moderation Action`, field `actionType: warnIdentity`.
- **Current state:** The final schema retains each warning as a ticket-linked moderation action but contains no karma, warning-point, or reputation balance.
- **Requirement context:** `SQ-01` clearly selected a warning action but described karma and Stack Overflow-like reputation only as possible mechanics.
- **Why it matters:** A score would require unrecorded rules for its starting value, increments, decrements, scope, decay, visibility, and appeals. Inventing those rules could make identical warnings affect identities inconsistently.
- **Disposition:** `docs/concepts/REQUIREMENTS.md` records the warning action and explicitly leaves reputation scoring undefined. No score requirement or schema field was invented.

### Canonical email and future mobile-number behavior

- **Affected schema item:** `docs/schemas/identity.yaml`, object `Identity`, fields `email` and `emailVerified`; `docs/schemas/human-authentication.yaml`, object `Human Authentication`, fields `identityId`, `email`, `issuer`, and `subject`.
- **Current state:** A human identity retains one verified profile email and may have multiple verified email-based authentication connections. No cross-record rule selects which address is canonical. The final schemas define no mobile-number authentication or profile field.
- **Requirement context:** `SQ-05` supports multiple account email addresses and use of an OIDC email during identity resolution, but it does not select a canonical address. Mobile numbers were described as a possible future addition rather than an MVP decision.
- **Why it matters:** Guessing a canonical-address or phone-number rule could merge unrelated identities, break legitimate sign-in, or create an unsupported recovery mechanism.
- **Disposition:** `docs/concepts/REQUIREMENTS.md` records multiple linked email authentication connections and OIDC email resolution. Canonical-address selection and mobile-number behavior remain non-actionable and were not converted into requirements.
